# 按现象排障

> 先取最少证据：操作系统与 Node 版本、驾驶舱版本/启动方式（独立端口还是 DSH 插件）、统计范围、复现步骤、期望与实际结果、脱敏错误码。
> 本文件是指导，不是权限：不读取对话正文/凭据，不替用户改 DSH 安全设置，不把“排障”做成“清空重装”。

## 先分清三条链路

| 链路 | 含义 | 不等于 |
| --- | --- | --- |
| 采集 | 读取 `~/.dsh/sessions` 的 usage 与元数据 | DSH 界面的实时数字 |
| 计算 | 定价、配速、今日建议、压缩预测 | 官方账单 |
| 呈现 | Web 仪表盘 / CLI / 插件子路径 | 数据本身正确 |

先确定坏在哪条链路，避免用一个数字证明其他数字正确。

## 常见现象

| 现象 | 先检查 | 下一步与验证 |
| --- | --- | --- |
| 页面空白 / 一直“加载中” | 服务是否在跑（`node src/cli.mjs serve`）、端口是否被占、浏览器控制台是否有 API 失败 | `curl http://127.0.0.1:7777/api/health`；`node src/cli.mjs status --json` 是否正常。不要先删缓存 |
| 启动报端口占用（`EADDRINUSE`） | 是否已有实例；7777 被谁占用 | 换端口 `serve --port 7800`；不要 kill 不明进程 |
| 有会话但总量为 0 / 金额为 `—` | 统计范围（周期/今日/7d）、`scan` 是否成功、模型是否在价格表 | `scan --json` 看 `errors`；未知模型 token 保留、金额 `—` 是**缺失≠0**，不是 0 |
| 数据比 DSH 界面少 4 小时 | 统计日界默认 Asia/Shanghai **04:00 换日** | 可在设置/配置改 `budget.dayStartHour`；不是丢数据，是口径不同 |
| 扫描慢 / 数字不更新 | 缓存/上次扫描时间、会话数量 | `scan --force` 只用于确认数据变化，不是默认修复；超大会话观察内存 |
| 出现“格式漂移/无法解析”警告 | DSH 是否刚升级，`session v3/v4` 是否变成 v5 | 保留警告与脱敏样本；升级适配层前不要猜格式或伪造 0 |
| zstd 解码失败 / 启动即报 Node 版本 | `node --version` 是否 ≥ 22.15 | 升级 Node；不要改用第三方解压依赖（零依赖是硬约束） |
| `doctor` 报 DSH 目录不可读/不存在 | 是否首次使用、`DSH_HOME` 是否被改道、权限 | 用默认 `~/.dsh` 或用户确认的目录；不要 `chmod`/移动 DSH 目录 |
| DSH 插件打开 404 / 白屏 | 插件条目是否写入并重启、profile 是否正确、`/dsh-cockpit` 前缀 | 先用独立端口确认仪表盘本身正常，再查插件；`install-plugin` 默认 dry-run |
| 金额与官方账单不一致 | 内置价格表版本与核对日期、缓存计价、未知模型 | 说明“估算非账单”；核对 `docs/PRICING.md`，不改历史数据来对齐账单 |
| 通知不出现 / 系统通知无权限 | 通知阈值、未读数、浏览器 Notification 权限 | 浏览器权限由用户自己授予；失败应静默降级，不影响仪表盘 |
| 备份/恢复失败 | 文件是否为 `GET /api/backup` 导出的 JSON、`schemaVersion` 是否兼容 | 恢复有校验；`restore --dry-run` 先预览；先备份再恢复 |
| 团队同步连不上 / 数据不更新 | 同步开关、endpoint、空间令牌、设备撤销状态 | 同步默认关闭且**非端到端加密**（管理员可读）；先解释边界再排障，不向陌生端点试传 |
| 标题敏感 / 想打码 | `ui.maskTitles` 配置 | 打开打码并刷新；不要为了排障把真实标题贴到公开渠道 |
| `npm test` 失败 | 是否在仓库根目录、Node 版本、`REAL_DATA` 是否被误开 | 先跑单文件定位；真实数据冒烟默认 SKIP，不能作为回归前提 |
| `lint` 失败 | 具体 `[RULE] file:line` 输出 | 按定位修；冻结文件的既有超长行只是告警，不要为告警改业务代码 |
| `coverage` 失败 | 输出里低于阈值的 `src/core/**` 文件 | 补 `node:test` 用例；不要改业务代码或伪造阈值 |
| Playwright E2E 起不来 | 是否装了 `@playwright/test` 与 Chromium；7811 是否被占 | `npx playwright install chromium`；无浏览器时用 `node test/e2e/smoke.node.mjs` |

## 插件与端口

- 独立服务默认 `http://127.0.0.1:7777/`；E2E 使用 7811 + 隔离临时 `DSH_HOME`。
- 插件挂载在 DSH GUI 同源子路径 `/dsh-cockpit`，前端通过 `window.__COCKPIT_BASE__` 拼接 API；不要把 `/api/` 写死。
- 先验证独立端口，再验证插件；两者都失败优先查 Node/依赖，只有插件失败查 profile 与 `cordis.patch.yml`。

## 源码排查

- 先读 `AGENTS.md` 按路由定位模块；算法改动必须升政策版本号并补测试；错误用 `CockpitError` + 稳定 code。
- 只要求诊断时给证据与建议，不动代码；要求修复时保留无关更改，用合成 fixture 加回归测试。
- 验证顺序：`node --test` → `node scripts/lint.mjs` → `node scripts/coverage.mjs` → `node scripts/audit-public.mjs` → E2E 冒烟。
- 真实数据只能本地临时使用，不进入仓库、issue、截图或报告。

## 需要反馈给维护者时

准备最小复现：版本/平台、启动方式、操作步骤、期望/实际、已检查项、脱敏错误、合成复现数据。
先给用户审阅，用户要求提交后才发 Issue；**永不**附带 `~/.dsh` 内容、对话正文、API Key、完整配置或未脱敏截图。
如果因权限/缺少环境无法继续，明确剩余检查，不把“没有继续报错”当作验收通过。
