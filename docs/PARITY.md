# DSH 驾驶舱 vs Codex Cockpit：全维度对照与复刻缺口

> 对照依据：Codex Cockpit v0.3.5 源码快照（293 文本文件，git blob SHA-1 293/293 校验）+ 四份专项评审；
> 我方 `dsh-cockpit` v0.1.0 实际代码 / 测试 / CI / 真实数据验收。
> 状态码：**F** 完全复刻 ｜ **A** 改造复刻（换语义/数据源）｜ **P** 部分 ｜ **N** 未复刻 ｜ **X** 主动不采纳（不适用）｜ **+** 新增。

## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 是什么关系？ | 不是分叉（fork），是**内核移植 + 数据层重写 + 形态换轨**：算法与产品模型来自 Codex Cockpit，数据源与运行形态属于 DSH |
| 复刻了多少？ | **v2 后：全量功能面 ≈83%；扣除 DSH 不适用项后可迁移能力 ≈89%**（v1 基线 62%/72%，补齐记录见 §10） |
| 最强的地方？ | **算法内核保真度最高（配速/计划/预测/成本 88–100%）**；工程方法（文档/审计/CI/政策版本）75–85% |
| 最大缺口？ | **用量分析的"多维下钻"**（任务级/成员级/日期筛选/子代理树）≈45%；**团队共享 0%**；**桌面形态 ≈10%** |
| 哪些"缺"其实不该补？ | 桌面悬浮窗（Tauri 壳）、签名自动更新、多 provider、云同步托管 —— DSH 场景不适用或本期不做 |
| 必须补的是什么？ | P0：任务级归因 + 日期/模型筛选、通知提醒、备份/导入导出、洞察文案；P1：日历详情、小票选择器、i18n、E2E |

## 2. 产品定位与形态：根本差异

| 项 | Codex Cockpit | DSH 驾驶舱 | 判定 |
|---|---|---|---|
| 解决的问题 | "Codex 周额度还剩多少、什么时候重置、钱花在哪" | "今天用了多少 token、花在哪、上下文何时被压缩" | **同类问题、不同数据源** |
| 数据源 | ①官方 usage API ②本地 app-server ③会话内嵌 rate_limits ④第三方重置情报 | 仅本地会话 `usage` + `contextWindow` + `compaction` 事件 | A（三链路 → 单链路自校准） |
| "重置"语义 | 官方额度重置（周额度 04:00） | **上下文压缩（compaction）** | A（1:1 映射改造） |
| 形态 | Tauri 桌面 App：悬浮窗 + 托盘 + 控制中心 | Web 仪表盘 + DSH 插件同源页 + CLI | **形态换轨** |
| 团队 | 可选自托管 Cloudflare Worker + D1 | 无（P2） | N |
| 分发 | 三平台安装包 + 签名增量更新 | 本地源码运行（无安装包） | X（不适用） |
| 目标用户 | 中文 macOS/Windows 个人开发者（实际 75% Windows） | DSH 重度用户（开发者本人） | 场景收窄 |

| X5 | 第三方重置情报对接 | DSH 无"重置情报"生态；本地压缩事件已能自校准 |
| X6 | 共享空间托管 SaaS | 与"本地优先/零遥测"冲突；P2 仅自托管 |

## 8. 判断：哪些"缺"是能力问题，哪些是选择问题

| 类型 | 条目 | 判断 |
|---|---|---|
| **能力缺口（该补）** | 任务级归因、日期筛选、通知、备份、洞察、日历详情、i18n、E2E | 补完才配称"驾驶舱" |
| **选择差异（可接受）** | 悬浮窗、托盘、自动更新、多 provider、团队托管 | DSH 形态下不适用；已在 PRD 记录理由 |
| **规模差异（正常）** | 代码量 8.7×、测试 27×、文档 2.4× | 单人 MVP vs 2.5 个月迭代产品；按里程碑补齐 |
| **能力相当（持平）** | 配速/计划/成本/缺失≠0/有界采集/政策版本/审计/文档结构 | 已达成企业级雏形 |
